# Toast de correo enviado

Cambio exclusivo de presentación en public/javascript/correos_marketing.js. Tras una respuesta de envío correcta se muestra: «Correo enviado. Las respuestas se recibirán en el buzón de <dirección>.» Se usa cuenta_salida si la respuesta ya la incluye y, en su ausencia, el correo de origen capturado al enviar. No se interpreta ni se modifica el texto técnico del backend, los estados de entrega ni el mensaje real del correo. No se alteran servicios, API/SMTP, remitentes, destinatarios, adjuntos, validaciones o claves de idempotencia.

Los toast de correo de otros módulos usan 3–3.5 segundos. Este módulo configuraba 3 segundos en éxito y 4.5 en error, pero la recarga existente a 650 ms cortaba el aviso de envío. Sólo el éxito de envío usa ahora 3.5 segundos y conserva el tiempo restante a través de esa misma recarga, mediante un mensaje temporal en sessionStorage por usuario. Se consume una vez, vence por fecha y no dispara peticiones al restaurarse. Los errores mantienen 4.5 segundos y los demás avisos de este módulo 3 segundos; el estilo, la ubicación, el icono y la recarga a 650 ms se conservan. El texto sigue insertándose con textContent.

Verificación manual aislada en Chrome con el JavaScript y Bootstrap reales, respuestas ficticias y reloj controlado: texto y dirección solicitados, preferencia por cuenta_salida cuando existe, persistencia tras la recarga, duración, una sola petición POST con los mismos campos, ausencia de repetición al recargar otra vez, error y borrador sin cambios. node --check y git diff --check aprobados. No se enviaron correos ni se accedió a producción. Por tratarse de un ajuste de presentación se usaron verificaciones temporales, sin añadir una batería de pruebas al repositorio.
